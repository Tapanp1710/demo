Structure & load-bearing facts

for whoever builds Phase 2–4

Stack

WordPress 6.8.8 · PHP 8.1.34 · Aalto 1.8 ("edgtf") with active child theme aalto-child 1.0.1 — whose stylesheet is 0 bytes (it currently overrides nothing via CSS) · WPBakery 6.8 · Slider Revolution 6.5.11 · jQuery 3.7.1 · LiteSpeed Cache 7.8 (minify, no combine) behind Hostinger CDN · prettyPhoto + Lightbox2 · CF7, Popup Maker, Chaty, Trustindex, reCAPTCHA, gtag ×2, Meta pixel. No GSAP, no Lenis.

Fragile selectors

vc_custom_1703800234843 is shared by all four floor-plan rows — Tower A vs B distinguishable only by prettyPhoto gallery ids -483/-654. The "IMMERSE YOURSELF" row and Tower B row have no id. /project-status/ is 20 identical unlabeled rows. Stable ids that do exist: #about-project #club-house #amenities #master-plan #floor-plan #location #general-specifications #contact-form.

Amenities grid reality

Desktop: 19 items, links navigate to /portfolio-item/… — no lightbox; images live in a separate index-matched background-div list using full-size originals. Mobile: an entirely different 9-item Owl slider with no links at all. Category filter: none (single category).

DOM booby trap

LiteSpeed rewrites every image to src="data:gif" data-src="real" with a <noscript> twin — 80 <img> tags = 40 real. Any script reading img.src or counting images must account for it.

Method

single runs · 1 Sep 2026, ~19:26–19:29 IST
  1. Static snapshot (curl, desktop-Chrome UA) + rendered post-JS DOM (headless Chrome 152 --dump-dom) — both archived in audit/data/.
  2. All 32 stylesheets downloaded and mined by extract.js: colours, font-families, @font-face, role rules, glyph classes, alt attributes.
  3. PageSpeed Insights API → 429 keyless daily quota (so no CrUX field data; lab only).
  4. Lighthouse 12.8.2 → 403 from the Hostinger edge in every configuration (default, native-UA, UA-override-disabled); its captured request headers are clean and curl replays of them return 200 — the WAF discriminates DevTools-instrumented traffic by a non-header signal.
  5. Fallback harness measure-cwv.js: CDP with only Page/Runtime/Emulation domains; metrics from the browser's buffered PerformanceObserver (LCP + element, layout-shift session windows, long tasks) + Navigation Timing. Mobile 412×823 @1.75 + 4× CPU throttle; desktop 1350×940. Network unthrottled — real-network mobile numbers will be worse.
  6. Hero MP4 probed remotely (range requests) with the ffprobe-static binary.

Re-run node audit/data/measure-cwv.js mobile out.json after the redesign for a like-for-like comparison.
